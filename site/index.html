The CLI

Point it at a URL. Read what's broken.

One command crawls the site, runs every check and prints a report. Output is a table, JSON, Markdown or CSV, so you can read it, pipe it into jq or save it as a file.

codoseo crawl https://example.com --format md

44 checks after every crawl.

Each check passes or fails and names the pages behind it. Results roll up into a health score from 0 to 100, weighted by severity and by how many pages are affected.

Fail the build before rankings drop.

CodoSEO is one static binary with no browser and no config file, so it drops into any pipeline. --fail-on critical exits with code 1 when the threshold is reached.

Async and politeBuilt on Tokio. Respects robots.txt and Crawl-delay, and backs off on 429 and 503.
Exit codes for CIGate a deploy on critical or warning findings, for crawls and for diffs.
Plain outputTable, JSON, Markdown and CSV. Audit files are portable and diffable.
Embed the cratesCore, crawler, checks and diff are published separately for your own Rust projects.
.github/workflows/seo.yml
- name: SEO audit
  run: |
    cargo install codoseo
    codoseo crawl ${{ env.SITE_URL }} \
      --format json -o audit.json \
      --fail-on critical

# later: compare against the last release
- name: SEO diff
  run: codoseo diff before.json audit.json --fail-on critical
Roadmap

The CLI is the first piece.

The crawler, checks and diff engine are shipped. The hosted and assistant-facing parts are not, and the dates are not fixed. Watch the repo for releases.

In development

Web app

A dashboard for continuous monitoring. Add a URL and get your first report without touching a terminal.

  • Scheduled crawls with change detection between runs
  • Alerts to Slack, Discord, email and webhooks
  • Health score trend and issue history
  • Self-host with docker compose up, or use a hosted plan
Planned

MCP server

Ask Claude, Cursor or any MCP client to audit a page, check a canonical or diff two crawls from your editor.

  • Crawl and audit a site from a chat prompt
  • Natural-language questions about issues
  • Suggested fixes for failing checks
  • Shares the engine with the CLI and web app
Planned

GEO checks

Visibility for AI answer engines, next to the classic SEO checks.

  • AI crawler rules in robots.txt, per user agent
  • llms.txt and llms-full.txt validation
  • Key content present in the raw HTML
  • Alert when a deploy blocks an AI bot
